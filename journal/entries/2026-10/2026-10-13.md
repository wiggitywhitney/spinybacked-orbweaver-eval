## 10:55:54 AM CDT - Commit: fe91a7b

### Summary
The developer updated documentation for evaluation processes across multiple PRDs and the shared evaluation template. The changes address two gaps discovered during a cross-run process review for commit-story-v2 run-29:

The CDQ-007 "structural guarantee" test now explicitly requires checking the guarantee by reading source code per function and per actual call site, rather than inferring it from a parameter's name. This clarification was added because taze run-17's first scoring pass incorrectly evaluated six files by relying on parameter names alone—a parameter named `relative` could be safe in one function while an absolute value flowed into an identically named parameter in a sibling function within the same file.

The IS scoring step now requires recording the exact app command alongside run timestamps in `run-summary.md`, so span counts can be compared across runs using the same command. This addresses a gap from release-it run-4, where the command was never recorded and its span count could not be compared with run-5's.

Both improvements were cascaded into the active evaluation PRDs (#161, #168, #177, #143) and the shared run template. Additionally, PRD #161's IS restore step now switches to deleting only the exact paths the instrument branch added, replacing a filename-pattern deletion approach that the PRD's own decision record had already superseded.
