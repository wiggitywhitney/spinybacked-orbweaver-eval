### Summary
The developer created a new trace filtering script and integrated it into the evaluation workflow to prevent false scores from contaminated shared trace files.

The core problem was that the shared trace file accumulates spans from every target and every earlier run. Scoring it directly had already produced a false positive—commit-story-v2 run-27 got a 70/100 when it should have been something else, because the scorer was reading another target's spans. The developer built `evaluation/is/filter-traces.js` to solve this by cutting the shared file down to just one run's spans before scoring.

The script keeps only spans from a specific service that started within a recorded time window, preserving the original OTLP envelope structure so the scorer still reads them correctly. It redacts machine identity (user name, host name, command lines, absolute filesystem paths) to avoid leaking local details, then re-scores the sanitized file to confirm the redaction didn't change the result. If the score changes, it refuses to write the output—a safety check to catch bugs in the redaction logic.

The developer also handled a subtle platform issue: the script uses `realpathSync` to resolve symlinks when checking whether it's being run as the main module. On macOS, where `/tmp` is symlinked, a plain string comparison would silently skip the main function and do nothing. This matters because the evaluation environment sometimes runs commands through symlinked directories, so the fix ensures the script actually executes.

The implementation includes detailed tests covering span filtering inside OTLP envelopes, redaction of sensitive attributes, score verification, and the command-line interface. Tests verify that the script works correctly when invoked through symlinked paths, fails cleanly with helpful error messages when required options are missing or no spans match, and preserves the JSON Lines format (one object per line, not an array).

The developer updated the shared evaluation run template's IS scoring instructions and the scoring README to call the new script. The template now records the run's start and end as nanosecond timestamps, runs the filter, and then scores the filtered file.
