**Unrubriced findings**:
- On the early-exit paths, the node spans claim a model request that never happens. In `technicalNode` and `dialogueNode`, `gen_ai.operation.name: chat`, `gen_ai.request.model`, `gen_ai.request.temperature` and `gen_ai.request.max_tokens` are set at span start (lines 489–494 and 555–560). They stay set when the `substantialUserMessages === 0` early return skips the model call. The registry marks `gen_ai.request.model` "Required when an AI model request is issued", so these spans report a chat request that did not happen.
- When a model call fails, the node spans show no error. The inner graceful catch swallows the failure, so the span ends with OK status, no token attributes and no failure attribute. Only the parent's `commit_story.journal.errors_count` reflects it. The outer catch can only fire for the `setAttribute` lines before the inner try. This conforms to NDS-007, but the per-node error signal is gone.
- The fallbacks record fabricated values. `gen_ai.usage.input_tokens/output_tokens ?? 0` would report 0 tokens if `usage_metadata` were absent, which looks the same as a real zero. `vcs.ref.head.revision ?? ''` would report an empty revision.
- The token counts can be counted twice. When traceloop is enabled, its `chat.anthropic` child span carries its own token usage. Setting `gen_ai.usage.*` on the INTERNAL node wrapper as well means any query that sums token usage across spans could double-count. This is an observation to confirm against the IS scoring trace.
- One note claim is broader than the rule. The note "the validator treats added if statements as non-instrumentation code" goes beyond NDS-003's actual behavior. Plain `x != null` guards pass, and only guards whose condition uses optional chaining are rejected (failure-deep-dives.md, "The guard gap reached further than the failed file"). The other note claims check out against the source: 4/19 span-to-function ratio, NDS-007 handling, `errors_count` as the only new attribute, and traceloop child spans (gated by `COMMIT_STORY_TRACELOOP`).
- Not a finding for this file: `generate_sections` sets `vcs.ref.head.revision` from `context.commit.hash`, which is the resolved SHA from `git show` output. It is not the literal `HEAD` from exemption-scope item 4, and `trace-artifact.md` shows the resolved SHA on this span.
