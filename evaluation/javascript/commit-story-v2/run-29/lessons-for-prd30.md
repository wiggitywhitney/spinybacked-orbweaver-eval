## Template Improvements

*(Process observations that belong in `docs/language-extension-plan.md`)*

- **The trace-capture protocol's completeness test reads an attribute the spans no longer carry.** `evaluation/trace-capture-protocol.md` defines a complete run as a `commit_story.journal.generate_sections` span whose `commit_story.journal.sections` contains all three section types. None of the 19 `generate_sections` spans in Datadog's 30-day retention carry that attribute, so the test cannot be applied as written. The protocol needs a completeness signal that the instrumented code emits.
- **The PRD names a span resource that does not exist.** Pre-run item 22 says to check `commit_story.journal.save_journal_entry`. That resource has no spans in retention; run-28 recorded the save span as `commit_story.journal.save_entry`, and span names vary by run because the agent names them. The template should tell the reader to derive the resource from what Datadog shows, the same way the post-run verification milestone already does.
- **Main-branch commit-story traffic now emits only Traceloop library spans.** With no manual instrumentation on main, organic main-branch runs produce LangChain/Anthropic root spans and no `commit_story.*` spans. The pre-run capture can therefore only find journal generation runs from instrument branches or IS scoring runs, which is why the latest one is run-28's.
- **The instrument command should set its own working directory.** Run-29's first launch ran from the eval repo, loaded the eval repo's `spiny-orb.yaml`, failed the prerequisite check, and exited 2 in 0.7s. The PRD said where to run the command but the command did not `cd` there. The template's instrument command should start with `cd <target-checkout> && set -o pipefail &&`, chained with `&&` so the pipeline does not run if the `cd` fails (D-10).
- **The log prints the model.** The `Total cost` line ends with the model ID, e.g. `$9.94 (claude-opus-5-5)`, and runs 26–28 show `claude-sonnet-4-6`. The template's model-recording step can cite the log as a cross-check, and earlier runs' models can be backfilled from their logs. Effort is not printed (D-10).
- **A failed file's result line has no attempt count.** `❌ FAILED` prints the validation error but not the number of attempts, so a log parser must count the `Attempt N` headers in the Agent thinking section instead.
- **The log-trace correlation query names a field the logs do not carry.** The post-run check's query `@otel_resource_attributes.service.instance.id:<id>` returns 0 logs; the logs carry the ID as `@service.instance.id`. The template should use `@service.instance.id`.
- **The two correlation rates measure different things.** Run-28's ~82% was sampled across the whole run window, which mixes hook runs on partly instrumented code; the PRD's instance-scoped query measures only the final code. Run-29 shows 5/5 scoped and 71/165 (43%) window-wide. The template should name one as the baseline, and the instance-scoped rate is the one that reflects the instrumented code.

- **"Attempts" in the log undercounts files committed through the function-level fallback.** `git-collector.js` and `summary-manager.js` print "3 attempts" but used three whole-file attempts plus a fourth function-level pass, which only their `.instrumentation.md` Validation Journey shows. The failure deep-dives milestone should read the Validation Journey for every committed file with 2 or more attempts, not only the log's count.
- **Fallback-committed files keep no agent thinking, and the log truncates multi-line validator messages.** The `.instrumentation.md` for `git-collector.js`, `summary-manager.js`, and `index.js` has no Agent Thinking section, and the log cut NDS-005's "Removed block" preview to one line. Rerunning the rule from spiny-orb's `dist/` on the original and the debug dump recovered the full message. The failure deep-dives milestone can name that technique.
- **Trace provenance should be labeled per trace, and span lookup should use span names, not prefixes.** The template's provenance rule reads `vcs.ref.head.revision` per cited trace, but most spans do not carry the attribute and some carry the literal `HEAD`, so a span-level reading marks spans from a matching process "unknown provenance" (run-29 D-13). Separately, the D-2 trace supplement's "derive a `resource_name` prefix per file" step does not work for commit-story-v2: `commit_story.journal.*` spans come from four files. Map span names to files from `startActiveSpan` calls on the instrument branch instead. Template candidate for step 12's checkpoint.
